# Medusa 1.8.6

- Index-node downloads use the library's download path: the same request builder, options and MP4 selector as a normal Medusa download (VideoRequest, shared with fetchVideo), with the node's height limit as the quality. The info JSON, thumbnail and description are fetched in separate calls after the video, so nothing extra rides on the video request.
- Settings > Index node > "Try WebM first" (default on, the behaviour before 1.8.6). On: the node tries WebM/Opus first, then the library's MP4 selector. Off: it goes straight to the MP4 selector. (The WebM first attempt is not removed: it is a setting.)
- A 403 on the video is retried once at the next height the library offers above the node's limit (720), then the job is released as before.
- Self-diagnosis: when a download still gets a 403 and there is no usable profile (or yt-dlp was updated, or the profile itself got a 403), the node tries up to 8 variants of the video request, one change at a time (thumbnail/info JSON with the video, WebM first flipped, height 720, then combinations), paced like other YouTube requests. A variant passes when its first 5 MB arrive. The diagnosis stops on a bot block or 429. The result is saved as the download profile, used for later downloads, shown in Settings (with reset) and written to the node record as downloadProfile with its tries.
- Every failed attempt records network, ytdlp (version), formats, client and tail (last 20 yt-dlp lines, URL query strings removed) in the job record next to lastError, and in the node log you can Share.
- Settings > Index node > "Test download": runs one URL through the node's path in the foreground, writes nothing to the store or profile, stops after 5 MB and shows the same fields. Three switches: WebM first, info JSON with the video, thumbnail with the video (the last two put those options back on the video request for the test only).
- New setting, off by default: "Also store my downloads in the index" (YouTube only; each download chooses Store only, the default, or Store and process). Write-only: Medusa reads nothing back. downloaded.json is created first, create-only (origin "medusa-library", real height); if it exists nothing is uploaded. Then info.json, description.txt, thumb.jpg, subtitle tracks and video.mp4 (8 MiB blocks). Store only marks the download job done; Store and process also creates the step jobs a node download creates. Uploads run in WorkManager under the node's conditions, resume, show progress in the status notification, and use mobile data only if allowed.
- Not verified on a phone or emulator. Whether the Samsung 403 is gone needs the phone.
